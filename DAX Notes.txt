Month column
------------
FORMAT( value, format_code )

format_codes:
	d	- day number (1 - 31)
	dd 	- day number with leading zero (01 - 31)
	ddd	- short weekday name ( Sun, Mon, ..., Sat )
	dddd	- full weekday name (Sunday, Monday, ..., Saturday)
	m	- month number (1 - 12)
	mm	- month number with leading zero (01 - 12)
	mmm	- short month name (Jan, Feb, Mar, ..., Dec)
	mmmm	- full month name (January, February, March, ...)
	yy	- two digit year number (26)
	yyyy	- four digit year number (2026)
	q	- Quarter


Month = FORMAT( [Date], "MMMM" )

DAX - Data Analysis eXpression
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Two types of expressions:
	- Calculated columns
		Expressions used to create columns in a table
		Uses row context
	- Measures
		Expressions used in Visuals (Report View)
		Uses row and filter context


Calculated columns
--------------------
- By default, uses row-context
- Don't use aggregate functions for calculated columns (except for ad-hoc purposes)

Column = SUM( [Hours] )

Column 2 = [Hours] / [TotalHours]


Total Billable Hours / Total Hours

30 / 40 -> 75% (0.75)



Column 3 =
SUMX(
	FILTER (
			ALL('Hours'),
			[Category] = "Billable" && [EmployeeID] = EARLIER( [EmployeeID])
		),
	[Hours]
)


Functions that end with 'X' such as SUMX, AVERAGEX, MINX, MAXX, COUNTAX, ... are iterator functions.


= SUMX( table, expression )
	-> The expression is executed for each row of the table
	-> The outcome of all the executions is aggregated

= FILTER ( table, filter1, filter2, filter3, ... )
	-> table is filtered based on the specified filters and creates a virtual table

= ALL ( table )
	-> Removes all the filters from the table:
		filters: visual, slicer, and filters pane



TotalRows = COUNTROWS( table )

Two types of tables
===================
1. Fact table
	Answers the question: What?
	It is always on the many side of the relationship
	It is filtered by dimension tables
	Most probably this table changes frequently
2. Dimension table
	Answers the question: How?
	It filters the fact table
	Most probably these tables don't change frequently
3. Snowflake
	A dimension table that is not directly related to fact table
	But sometimes we can integrate snowflakes into a dimension




Measures
`````````````

Total Billable Hours =
SUMX(
	FILTER( 'Hours', 'Hours'[Category] = "Billable" ),
	'Hours'[Hours]
)

Total Hours =
SUMX(
	'Hours',
	'Hours'[Hours]
)

% Utilization = DIVIDE ( [Total Billable Hours], [Total Hours] )
